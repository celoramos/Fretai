# Cotação com preço dinâmico — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O preço do frete passa a ser calculado pela plataforma: o cliente cota por categoria de carga, recebe uma opção por veículo, e cria o frete a partir da cotação com preço travado.

**Architecture:** Tudo dentro do módulo `frete` (api → application → domain ← infra). O cálculo é uma classe de domínio pura (`TabelaPreco`) montada a partir do `application.yml`; a cotação é uma entidade persistida que o frete consome uma única vez. O relógio entra por um `Clock` injetado.

**Tech Stack:** Java 21, Spring Boot 4.1, Spring Data JPA, Flyway (PostgreSQL + H2 nos testes), JUnit 5, Mockito, ArchUnit.

**Spec:** `docs/superpowers/specs/2026-10-17-cotacao-design.md`

## Global Constraints

- Dinheiro sempre `BigDecimal`, 2 casas, `RoundingMode.HALF_UP`.
- Nenhum valor de preço no código: taxas, R$/km, mínimos, multiplicadores, validade e fuso vêm de `fretai.preco.*`.
- Fuso `America/Sao_Paulo`; todo "agora" vem de um `Clock` injetado.
- O peso **não** altera o preço.
- Telefone do motorista só aparece na resposta com status `ACEITO` ou `EM_TRANSITO`.
- Migrations novas: `V4`, `V5`, `V6`. **Não editar** `V1`–`V3`.
- Regras do `ArquiteturaTest` valem: domain não depende de application/api/infra; application não depende de api/infra; sem ciclos entre módulos.
- Mensagens e nomes em português, no estilo do código existente (comentário explica o porquê, não o quê).
- Testes rodam com `.\mvnw.cmd test` (PowerShell) a partir da raiz do projeto.

## Review Focus

1. **Duas requisições usando a mesma cotação ao mesmo tempo** → só um frete pode nascer. Índice `UNIQUE` em `frete.cotacao_id` (Task 6) + teste de integração que cria o frete duas vezes com a mesma cotação e espera 409 (Task 7).
2. **Cotação vencida por segundos** (`agora == validaAte`) → já é expirada. Teste de borda em `CotacaoTest` (Task 4).
3. **Peso exatamente no limite** (200 kg em `LEVE`) → aceito; 200,01 kg → recusado sugerindo `MEDIA`. Testes em `CategoriaCargaTest` (Task 2).
4. **Frete antigo sem `tipo_veiculo`** (criado antes da V6) → qualquer motorista pode aceitar. Teste em `FreteTest` (Task 6).
5. **BrasilAPI de feriados fora do ar** → a cotação sai sem multiplicador de feriado, sem 503. Teste em `CotacaoServiceTest` (Task 5).

  - `final class TabelaPreco`:
    - `TabelaPreco(Map<TipoVeiculo, PrecoVeiculo> veiculos, Multiplicadores multiplicadores)` — `IllegalArgumentException("Falta configurar o preço do veículo X")` se faltar algum `TipoVeiculo`.
    - `Multiplicador multiplicador(LocalDate dataColeta, LocalDateTime agora, boolean feriado)`
    - `BigDecimal preco(TipoVeiculo tipo, BigDecimal distanciaKm, Multiplicador multiplicador)`
  - Bean `TabelaPreco` (em `PrecoConfig`) e bean `Clock` = `Clock.system(ZoneId.of(fuso))` (em `RelogioConfig`, lendo `fretai.preco.fuso`).
  - `@ConfigurationProperties("fretai.preco") record PrecoProperties(Duration validadeCotacao, String fuso, Map<TipoVeiculo, Veiculo> veiculos, MultiplicadoresProps multiplicadores)`; `PrecoConfig` tem `@EnableConfigurationProperties(PrecoProperties.class)`.

Regra do multiplicador, nesta ordem de prioridade em caso de empate de valor: `FERIADO` > `NOTURNO` > `FIM_DE_SEMANA`; vale o maior valor entre os que se aplicam; nenhum → `Multiplicador.NENHUM`.
- fim de semana: `dataColeta` é sábado ou domingo.
- noturno: `dataColeta.equals(agora.toLocalDate())` **e** a hora de `agora` está na faixa `[noturnoInicio, noturnoFim)` atravessando a meia-noite.
- feriado: parâmetro `feriado == true`.

Preço: `max((taxaSaida + distanciaKm × porKm) × multiplicador, minimo)`, arredondado no fim.
